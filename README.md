# Personal Work OS

このリポジトリは、個人の仕事を設計し、実行し、レビューするための思考OSです。

AIを使って、仕事を丸投げするためのものではありません。

AIと協働しながら、自分の仕事の設計品質を高めるためのものです。

## 1. このリポジトリは何か

このリポジトリは、仕事を次のような形で扱えるようにするための実践的な設計です。

- わかりやすく整理できる
- レビューしやすい
- 小さな単位で実行できる
- 不確実性に対応できる
- フィードバックで改善できる

これは、Claude CodeのようなAI支援ツールと一緒に使うことを前提にしています。

このリポジトリは会社のナレッジベースではありません。
顧客情報、社内資料、機密情報、案件固有の情報を保存する場所ではありません。
汎用的に使えるよう、一般化して作っています。

## 2. なぜ作るのか

多くの仕事は最初の依頼が曖昧で、作業に入る前に定義が不足しています。
その結果、次のような状態になりやすいです。

- 目的が曖昧になる
- 前提が不明瞭になる
- 分解が粗くなる
- 依存関係が見落とされる
- 手戻りが増える

このリポジトリは、その問題を減らすために、仕事の設計を明示的に行うための土台です。

大事なのは AI に全部考えさせることではなく、
AI を使って自分の仕事の設計をよくすることです。

AIには次のような役割を期待します。

- 分解する
- 反論する
- 見落としを探す
- 条件を整理する
- 計画をレビューする
- 文章や構造を整える

## 3. AIとどう使うか

曖昧な仕事、大きな仕事、高リスクの仕事に対して使います。

典型的な使い方は次の流れです。

1. ざっくりした依頼を受ける
2. その仕事を定義する
3. サブゴールに分解する
4. 必要な成果物と入力を整理する
5. リスク、前提、依存関係を見直す
6. 小さな単位で実行する
7. 現実が変わったら計画を更新する

AI は最終判断を代わりにするものではありません。

人間が担うのは次の部分です。

- 最終目的
- 最終判断
- 優先順位
- 重要なトレードオフ
- 受け入れ可能なリスク
- 成果物の妥当性

## 5. Core Philosophy

このリポジトリは、次のような原則に基づいています。

- 仕事を定義してから実行する
- Work Plan はタスクリストではなく、仕事を成立させる設計である
- 大きな仕事は実行可能な子タスクへ分解する
- 不足している情報は推測で埋めず、明示する
- AI は思考の相棒であり、意思決定者ではない
- 前提が崩れたら、元の計画に固執せず更新する
- 目的は計画を守ることではなく、仕事を前に進めること

## 6. 今後どう育てていくか

最初は小さく始めます。
最初に確立したいのは次の領域です。

- 仕事の定義
- 計画作成
- 分解
- レビュー
- 修正

実際の仕事で繰り返し出てくるパターンが増えたら、次のような Skill を追加していく想定です。

- ステークホルダーとのやり取り
- 調査と事実確認
- リスク整理
- 設計レビュー
- 意思決定の記録
- 提出前の最終確認

ただし、新しい Skill を増やすときは、原則・ワークフロー・チェックリスト・事例を混ぜないようにします。

- Principle: なぜそうするのか
- Workflow: どう進めるのか
- Checklist: 何を確認するのか
- Example: 実際に起きた事例

## まとめ

このリポジトリは、個人の仕事をより設計的に進めるためのOSです。

AI は、仕事を代行するためではなく、
仕事の構造を整え、欠けを埋め、計画の穴を見つけ、修正を早くするために使います。

目的は「AIに任せること」ではなく、
「自分の仕事の質を上げること」です。
