# Workflow: レビューと更新

## 目的

状況が変わったときは、壊れた設計を無理に守るのではなく、前提と計画を更新する。

## フロー

変化を検知
→ 影響範囲を特定
→ 前提を更新
→ Work Plan を更新
→ 再開

## 手順

### 1. 変化を検知する

新しい情報、制約、文脈が元の前提を変えたときに気づく。

### 2. 影響範囲を特定する

計画のどこが、成果物が、依存関係が影響を受けるのかを確かめる。

### 3. 前提を更新する

今わかっていること、まだ不明なこと、修正が必要な仮定を明示する。

### 4. Work Plan を更新する

変化した現実に合わせて計画を修正する。

### 5. 再開する

更新した前提に基づいて、実行を再開する。

## 原則

環境が変わったら、計画も変わるべきだ。
